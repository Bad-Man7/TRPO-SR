# Архитектура приложения "Заметки с тегами"

## Общая схема

┌─────────────┐ ┌──────────────┐ ┌──────────────┐
│ Клиент │────▶│ Flask Server│────▶│ SQLite DB │
│ (Browser) │◀────│ (app.py) │◀────│ (notes.db)│
└─────────────┘ └──────────────┘ └──────────────┘


## Выбранные технологии

### Flask
**Почему выбран:**
- Легковесный фреймворк, быстрый в освоении
- Простая маршрутизация (декораторы @app.route)
- Встроенная поддержка шаблонов Jinja2
- Идеален для небольших проектов

### SQLite
**Почему выбрана:**
- Не требует отдельной установки сервера
- Хранится в одном файле (notes.db)
- Достаточно для небольшого приложения
- Поддерживает SQL-запросы

### HTML + Jinja2
**Почему выбраны:**
- Простота создания динамических страниц
- Наследование шаблонов
- Автоматическое экранирование (защита от XSS)

## Структура базы данных

Таблица `notes`:
- `id` (INTEGER PRIMARY KEY) — уникальный номер заметки
- `title` (TEXT) — заголовок
- `content` (TEXT) — текст заметки
- `tags` (TEXT) — теги через пробел (#работа #важное)

## Основные маршруты

| Метод | Маршрут | Описание |
|-------|---------|----------|
| GET | / | Главная страница со списком всех заметок |
| GET/POST | /add | Добавление новой заметки |
| GET/POST | /edit/<id> | Редактирование заметки |
| GET | /delete/<id> | Удаление заметки |
| GET | /?tag=<name> | Фильтрация по тегу |

## Основные функции

- `get_db()` — подключение к базе данных
- `process_tags()` — обработка тегов (добавление #, удаление дубликатов)
- `index()` — отображение главной страницы
- `add()` — добавление заметки
- `edit()` — редактирование заметки
- `delete()` — удаление заметки

## Обработка тегов

Теги хранятся как строка с разделителями (пробелы). Функция `process_tags()`:
1. Разбивает строку на отдельные теги
2. Удаляет дубликаты
3. Приводит к нижнему регистру
4. Добавляет символ `#` в начало
5. Собирает обратно в строку
